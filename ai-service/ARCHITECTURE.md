# teethsee AI 目标架构

## 结论

最优方案不是把训练、识别和报告全部塞进一个“万能 Agent”，也不是依赖用户电脑的显卡。teethsee 将模型训练、在线推理和 Agent 报告拆成三个可替换层：

1. **云端训练层**：按需租用 GPU，使用牙医标注数据训练和评估；
2. **模型推理层**：在 Linux CPU 服务或本地电脑上运行经过签名和版本控制的 ONNX 模型；
3. **Agent 报告层**：只读取模型输出的结构化证据，生成用户报告、追问和历史小结。

因此未来可以替换模型、训练平台或语言模型，而不需要重做用户档案、网页和医院接入。

## 模型路线

### v0.1：开源基线分类

- 输入：单张口内照片；
- 输出：六类概率和图片质量；
- 目的：打通真实推理链路、建立本机与服务器性能基线；
- 限制：不定位牙齿，不识别食物残留，没有健康类别。

### v0.2：牙位定位

- 使用多视角牙齿分割网络建立 FDI 牙位掩码；
- 输出每颗牙的编号、可见面和定位置信度；
- 使用自有数据重新训练权重，避免第三方非商业权重限制。

### v0.3：异常区域多任务模型

- 共享视觉骨干，分别输出龋齿、牙结石、牙龈异常和可见残留掩码；
- 增加 `unknown/无法判断`，不能把每张图强制归入疾病类别；
- 使用牙医双人标注、争议复核和患者级数据划分；
- SAM2 等基础模型只用于加快标注，不直接生成最终判断。

### v0.4：长期同牙同区域匹配

- 先按 FDI 牙位缩小搜索范围；
- 再使用局部特征、关键点和几何配准确认同一牙面；
- 保存模型版本、牙位、区域、证据图和不确定度，支持多年回顾与重新分析。

## 训练与验收原则

- 训练集、验证集和测试集必须按患者分开，防止同一患者照片泄漏到不同集合；
- 单独建立真实冲牙器摄像头测试集，不能只使用 DSLR 或网络图片；
- 按每个类别分别观察灵敏度、特异度、精确率、召回率、校准误差和拒答率；
- 按设备、医院、人群、拍摄角度和图像质量做分层测试；
- 新模型先影子运行，再小流量发布，可一键回滚到上一版本；
- 原始模型输出和 Agent 文案分开存储，语言模型不得篡改概率、牙位和证据区域。

## 部署方式

- **演示电脑**：本地 ONNX Runtime，CPU 即可，无 API Key；
- **正式推理**：Linux CPU 容器，按请求水平扩容；需要时再使用云 GPU；
- **训练**：按小时租用云 GPU，训练结束即释放；
- **模型仓库**：保存模型哈希、数据版本、评估报告和回滚版本；
- **网页与 iOS**：只调用稳定的推理 API，不关心后端使用哪种模型框架。
