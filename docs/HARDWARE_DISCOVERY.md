# 样机与 iOS 接入调查

版本：0.1  
状态：阶段 0 已确认

## 1. 当前已知

- 已有能输出摄像头画面的真实冲牙器样机；
- 当前在手样机的摄像头通过 USB 连接，黑客松现场优先使用该版本；
- 另有 Wi‑Fi 版本，但当前不在现场，原 Wi‑Fi 接入方向继续保留；
- 现有软件可以实时观看样机画面；
- 尚未确认底层视频协议、控制接口和可用开发资料；
- 尚未形成同牙同区域的标准清洁前后样张或视频集。

本文件不推测样机规格，只定义进入开发前必须确认的事实。

### 1.1 当前演示电脑检查

2026-07-24 的本机只读检查未发现外接 USB 摄像头设备。网页接入能力已经实现，但正式演示前必须插入样机，并确认它出现在系统或网页的摄像头列表中。

## 2. 调查原则

- 先读取厂商文档、现有 App 信息和授权资料；
- 只做只读观察和受控连接测试；
- 不破解固件、不绕过认证、不扫描无关网络；
- 不修改样机配置，除非有明确说明和用户授权；
- 记录每项结论的证据来源、固件版本和测试日期。

## 3. USB 与 Wi‑Fi 连接清单

需要确认：

- USB 样机能否被 macOS 识别为标准摄像头设备；
- USB 接口、转接器、数据线和独立供电要求；
- 设备接入后显示的摄像头名称；
- 插拔、休眠、被其他软件占用后的恢复行为；
- 浏览器相机权限拒绝后的恢复路径；
- 多个摄像头同时存在时如何选择正确样机；
- USB 画面是否需要厂商驱动或专用 SDK；
- 样机创建热点还是加入现有局域网；
- SSID、连接流程和首次配对方式；
- 是否要求系统本地网络权限；
- 是否需要密码、令牌或设备绑定；
- 同时允许多少个客户端；
- 断线与自动重连行为；
- App 切后台、锁屏和来电后的行为；
- 无互联网时能否继续看画面和拍照；
- 设备发现方式；
- IP 地址是否固定；
- 多台设备如何区分；
- 固件版本和设备唯一标识如何读取。

## 4. 视频与控制协议清单

需要确认：

- USB 视频是否符合系统标准摄像头接口，或属于厂商私有协议；
- USB 视频支持的像素格式、分辨率和帧率；
- 视频协议：RTSP、MJPEG、HLS、WebSocket 或厂商私有协议；
- 传输端点和握手流程；
- 编码格式；
- 分辨率；
- 帧率；
- 关键帧间隔；
- 实际端到端延迟；
- 是否含音频；
- 是否支持抓取原始帧；
- 拍照是手机截帧还是设备原生拍照；
- 是否支持开始、停止、亮度或灯光控制；
- 控制命令是否有确认和错误码；
- 是否存在官方 SDK、头文件、示例或协议文档；
- SDK 支持的最低 iOS 版本和架构；
- SDK 或协议的使用授权。

任何未确认项都标记为“未知”，不得用假设进入正式实现。

## 5. 图像能力清单

需要实际测量：

- 有效分辨率与压缩质量；
- 口腔内近距离对焦范围；
- 自动曝光和白平衡稳定性；
- LED 亮度与反光；
- 水滴附着后的影响；
- 冲水时的抖动和遮挡；
- 牙齿在画面中的占比；
- 不同牙面能否稳定拍到；
- 手机截帧与设备原图的差异；
- 长时间使用后的温度、断流或画质变化。

## 6. iOS 接入边界

设备连接适配层向上提供统一能力：

- 发现设备；
- 连接；
- 获取连接状态；
- 获取视频帧；
- 拍照；
- 可选设备控制；
- 断开；
- 错误与恢复建议。

业务层不直接依赖某个视频协议或厂商 SDK。若未来更换样机，只替换适配层。

iOS 侧需要在开发前确认：

- 最低支持版本；
- USB 样机是否能被目标 iPhone 与转接器识别；
- USB 配件的供电、权限和系统支持范围；
- 本地网络权限说明；
- Wi‑Fi 切换体验；
- 后台和锁屏限制；
- 视频解码能力；
- 相机画面内存占用；
- 原图保存位置；
- 设备凭据的安全存储；
- 是否允许同时访问互联网 AI 服务。

## 7. 标准样张采集计划

在用户授权且样机连接方式确认后，采集演示数据。

每组至少包含：

- 用户或测试对象匿名编号；
- 牙齿身份；
- 牙面区域；
- 拍摄时间；
- 设备和固件版本；
- 光照、距离和角度；
- 清洁前照片；
- 清洁后同区域照片；
- 明显食物残留场景；
- 无明显残留场景；
- 模糊、反光、水滴、过暗等失败样张；
- 拍摄者对位置和质量的确认。

样张用于 Demo 质量检查、定位和对比验证，不自动作为疾病训练样本。

## 8. 建议的受控调查步骤

1. 收集样机型号、固件、现有 iOS App 版本及可用资料；
2. 在演示电脑上确认 USB 样机能被系统摄像头列表识别；
3. 验证浏览器授权、设备选择、实时画面、截帧和断开；
4. 记录手机连接 Wi‑Fi 的完整过程；
5. 观察画面启动、停止、切后台和断线恢复；
6. 在授权测试环境内识别视频与控制接口；
7. 测量分辨率、帧率和端到端延迟；
8. 验证截帧原图质量；
9. 记录错误状态和恢复方法；
10. 形成适配层输入/输出确认表并采集最小标准样张。

## 9. 阶段 1 开发入口条件

至少确认：

- 设备连接模式；
- USB 样机在目标演示设备上的系统识别结果；
- 视频协议与端点；
- 编码、分辨率和帧率；
- 拍照实现方式；
- 是否存在认证或设备凭据；
- 断线恢复方式；
- 可用 SDK/协议资料及其使用边界；
- 一组可重复拍摄的测试样张；
- 目标 iPhone 和 iOS 版本。

当前最重要的短期输入是：**USB 样机是否作为标准摄像头被演示电脑识别，以及真实设备名称、分辨率、帧率和稳定性。** Wi‑Fi 版本的协议与 SDK 调查继续保留为后续接入项。
